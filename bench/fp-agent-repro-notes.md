# FP-Agent reproduction, Sep 25 2026, private

Primary sources: [paper](https://arxiv.org/abs/2605.01247), [code](https://github.com/ethanbwang/fp-agent), [OSF data](https://osf.io/j6b5p/overview?view_only=ac4ad89fbde540269aaaa85a2249cad6). Authors' published OSF split is 6,175 train and 1,544 test; downloaded feature vectors and saved all-class XGBoost models. Ran `bench/fp-agent-reproduce.py` with the author's models and test split using Python 3.13, NumPy 2.3.4, scikit-learn 1.7.2 and XGBoost 3.1.1. Results: browser-only 82.12% accuracy; behavioral-only 99.94%; combined 100% (1,544/1,544). Human class 109/109 correctly identified under all three. These numbers reproduce the study on its own split; **they are not our model's numbers**, and the study's held-out split is not necessarily independent by participant, task, site, or agent version. We later audited split overlap as below; we have not tested genuinely unseen agents on matched sites. No broad or temporal generalization can be inferred.

We later downloaded the OSF raw JSON privately (~4.3 GB), streamed a minimized event adapter, and applied our unchanged behavioral-only scorer: 0/7,182 raw agent sessions and 0/546 human sessions flagged. The raw corpus and derived events stay in ignored `data/`, not in this package. This is not a fair head-to-head with the authors' 468-feature trained model, which uses different inputs. Competing against a perfect score on one split requires a harder, independent benchmark, not tuning on that test set. See the main benchmark for details.

## Split audit (private, not an accusation)

We hashed the published numeric feature vectors. In the authors' random trial-level train/test split, 1,542/1,544 test rows have a browser fingerprint vector exactly equal to a train row. Only 77 distinct 418-element browser vectors occur across 6,175 training rows; 276 overlapping test browser vectors also appear under a different class, so exact overlap is not itself a trivial label lookup. Behavioral vector exact duplicates occur for 40/1,544 test rows, and combined-vector duplicates for 37/1,544. Those figures describe repeated feature vectors, not necessarily copied trials.

To check participants, we matched the published OSF feature vectors back to their metadata strings in `feature_vectors.json`. The human `task_name` token at index 1 is treated as `visitor_id` in the authors' own data retrieval code (`classifier_training/src/classifier_training/data_processing.py`). Train contains 63 distinct such tokens, test 50, with 47 in both. Thus 94% of distinct test-side human visitor tokens occur in training. The published split tests trials from largely familiar visitor IDs; it does not establish unseen-person performance. A visitor-grouped holdout, a new site and agent versions, and an independent corpus are needed to test generalization. It remains possible for a genuinely strong model to pass those tests, but the published 100% is not proof.

We tested whether visitor overlap alone explains the result: trained a *new* XGBoost model on the released vectors with 13 human visitor ID tokens held out, 89 human test rows, and a fixed trial-level split for agent classes. On that one-seed diagnostic, behavioral features classified 1,500/1,503 test rows correctly with 0/89 human errors; combined features classified 1,503/1,503 correctly. This is not a new-agent, new-site or multi-seed test, and cannot replace a prospective benchmark. It does show that the published random split's visitor overlap alone is not a sufficient explanation for the strong performance. The code is `bench/fp-agent-group-split.py` and requires the downloaded OSF vectors. No author code or data is redistributed in the ZIP.

## Version-path semantics and exploratory OOD test

The released metadata assigns all 546 human trials to one `website_version` token, while each agent class uses disjoint other tokens. We inspected the source: `honey_website/README.md` describes these as random ten-character strings, each deployed at `<domain>/<version>/`, and server.py serves the same static site tree under each version path. Therefore the disjoint tokens **do not establish different site designs or site-content leakage**. They separate collection campaigns/paths; whether campaign, time or environmental differences drive any signal requires more evidence. Every class covers shopping, flight booking, and forum tasks on the one honey site. This is a stronger controlled same-site experiment than a mere version-ID table suggests. The key open generalization question is a genuinely new site, browser environment and time.

`bench/fp-agent-leave-class-out.py` trains a fresh binary human/agent XGBoost model from behavioral or combined vectors and evaluates each agent class excluded from training, with 13 human visitor IDs (89 trials) excluded from training. Behavioral held-out-agent detection ranges 983/988 (Manus) to 1,139/1,139 (Browser Use), with 0/89 held-visitor human FPs per run; combined is similar. This is exploratory, on the same honey site's three task categories and likely similar collection environments. It is not comparable to the authors' eight-class test, and it does not establish prospective unseen-site or agent-version robustness. The code is https://github.com/ethanbwang/fp-agent/blob/8709c4fe/honey_website/README.md (version-path semantics) and https://github.com/ethanbwang/fp-agent/blob/8709c4fe/honey_website/server.py (server routing).

## Leave-one-task-category-out diagnostic (fresh models)

`bench/fp-agent-leave-task-out.py` trains new eight-class XGBoost models on two of the honey site's task categories, tests the third, and uses fixed max depth 6, 150 trees, learning rate 0.1, seed 32. Behavioral-only accuracies: shopping 1,942/2,609 (74.43%), flights 1,771/2,585 (68.51%), forums 2,085/2,525 (82.57%). Combined browser+behavior: shopping 2,531/2,609 (97.01%), flights 2,500/2,585 (96.71%), forums 2,357/2,525 (93.35%). Human misclassification was 0/165, 0/188 and 0/193 in the respective tests. The eight-class agent class errors are not the same as human-vs-automated misses: behavioral agent-to-human misses are 1/2,444 shopping, 7/2,397 flights, 57/2,332 forums; combined misses are 3/2,444, 5/2,397, 18/2,332. Thus most errors are wrong *agent type*, not misidentified human. Human visitor IDs may recur across categories; same site and agent implementations, no new-site claim. The authors themselves include a task-holdout script; this implementation is a diagnostic, not a reproduction of their exact training defaults.

A deliberately simple one-feature diagnostic (`bench/fp-agent-minimal-rule.py`) chooses the largest mouse-movement-count threshold allowed by a 5% empirical FPR on 457 training human trials. Threshold <=28 moves flagged 22/457 train humans, 1/89 held-visitor humans and 1,354/1,409 trial-split agents. It is worse than the full FP-Agent model, and absence of movement is unsafe to apply to keyboard-only, mobile or accessibility-assisted people. This is an explanatory sanity check on one site, not a deployable detector or a SOTA result.
